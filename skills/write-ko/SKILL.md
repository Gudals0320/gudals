# write-ko: 한국어 글쓰기

독자가 적게 추측하도록 글을 작성하라. 구체적인 문장을 만들려고 없는 정보를 채우지 마라. 아래 원칙을 초안의 내용·구조·표현을 선택할 때 적용하라.

`/gudals:write-ko` 뒤에 붙은 인자가 있으면 그 인자를 작성 요청과 입력 정보로 삼아라. 인자가 없으면 대화의 현재 요청을 기준으로 삼아라.

## 우선순위

사용자의 요청, 목적, 독자, 형식과 말투를 기준으로 삼아라. 이 스킬 내부에서 선택이 충돌하면 다음 순서를 따르라.

1. 사실, 조건, 예외, 부정, 수치, 단위와 확신 수준의 정확성
2. 독자에게 필요한 정보와 명확한 논리 관계
3. 문맥에 맞는 자연스러운 한국어와 글의 흐름
4. 간결함과 형식의 일관성

짧게 쓰거나 명령형으로 쓰기 위해 상위 기준을 훼손하지 마라. 경고도 실제 위험의 조건과 가능성을 정확하게 표현하라.

## 작성 순서

### 1. 무엇을 위한 글인지 정하라

요청에서 목적, 독자, 전달할 핵심, 원하는 형식과 말투를 파악하라. 이미 알 수 있는 내용을 다시 묻지 마라. 합리적인 형식 선택은 직접 하되, 결론이나 행동을 바꿀 핵심 정보가 없으면 필요한 사항만 질문하라.

사용자가 질문에 답할 수 없는 상황(자동 실행, 배경 작업)이라면 질문으로 멈추지 마라. 작성할 수 있는 부분을 모두 작성하고, 핵심 공백은 초안에 자리표시자로 남겨라.

### 2. 사용할 정보를 구분하라

제공되거나 확인된 사실, 그 사실에서 도출하는 해석, 제안, 가정과 예시를 구분하라. 원인을 설명할 자료가 없으면 원인을 만들지 마라. 숫자·담당자·날짜·인용·출처도 같은 원칙을 적용하라.

단순한 정보 누락을 실제 미확인 상태로 단정하지 마라. 입력에 원인이 없다는 사실만으로 본문에 '원인은 아직 확인되지 않았다'고 쓰지 마라. 필요하면 사용자에게 확인하거나, 요청된 초안에 `[원인 확인 필요]`처럼 표시하라.

파일 읽기, 검색, 웹 조회 같은 도구를 사용할 수 있고 사용자가 조사를 요청했다면, 출처를 확인한 뒤 그 내용을 사실로 사용하라. 도구로 확인하지 않은 내용은 확인된 사실처럼 쓰지 마라. 코드나 문서를 읽고 글을 쓸 때는 읽은 범위를 넘어 추측한 동작을 사실로 적지 마라.

### 3. 독자가 이해할 순서를 설계하라

설명·분석·보고에서는 핵심 판단이나 현재 상태를 먼저 제시하고 근거를 연결하라. 배경이 먼저 필요한 교육 글이나 서사는 그 목적에 맞게 전개하라. 한 문단에는 하나의 주제를 두고 새 정보가 앞의 정보에 어떻게 이어지는지 보여라.

### 4. 의미를 보존하는 표현을 고르라

- 핵심 개념과 대상의 이름을 일관되게 써라. 용어 통일을 이유로 서로 다른 대상을 합치지 마라.
- 정확도가 유지되는 범위에서 익숙한 말을 써라. 전문 용어는 필요한 정의와 독자에게 미치는 영향을 함께 설명하라.
- 한 문장에는 하나의 중심 내용을 담아라. 그 내용을 구성하는 원인·조건·대조·목적·동시성은 함께 표현하라.
- 행위자와 대상이 불분명하면 밝혀라. 이미 명확한 주어를 반복하거나 알려지지 않은 행위자를 만들지 마라.
- 불필요한 명사화·피동·사동·상투적인 도입을 줄여라. 권고·의무·가능·완료·추정의 차이를 보존하라.
- 불확실성은 대상과 근거를 드러내라. '일 수 있다'를 '이다'로, '약 30분'을 '30분'으로 바꾸지 마라.
- 문장 길이와 형식은 읽기 흐름에 맞춰 선택하라. 어절 수나 종결어미 반복만으로 문장을 분리하거나 합치지 마라.

### 5. 글의 목적에 맞춰 완성하라

필요한 설명을 남기고 반복만 덜어내라. 비교에는 작은 표도 허용하고, 순서가 있는 동작에는 번호를 사용하라. 비유가 이해를 돕는다면 사용하되 실제 개념과의 차이를 밝혀라.

행동이나 결정이 필요한 글에만 다음 행동을 제시하라. 설명을 마친 글에 의례적인 제안이나 질문을 덧붙이지 마라. 사용자가 결과물만 요청하면 작성 과정, 점검표, 적용한 규칙 목록을 출력하지 마라.

결과물을 파일로 저장하도록 요청받았을 때만 파일을 만들어라. 그렇지 않으면 글 자체를 응답으로 제시하라. 글 전체를 코드 블록으로 감싸지 마라. 사용자가 그대로 복사해 쓰려는 메시지나 UI 문구처럼 경계가 필요한 짧은 결과물에만 인용 또는 코드 블록을 사용하라.

## 세부 참고 문서

참고 문서는 이 스킬 폴더의 `references/` 아래에 있다. 필요한 문서만 Read 도구로 읽어라.

- 처음 작성하거나 장르·구조·문법 선택을 판단할 때 [작성 규칙](references/writing-rules.md)을 읽어라.
- 더 쉬운 말이나 짧은 표현을 선택할 때 [표현 선택](references/expression-choices.md)을 참고하라. 자동 치환표로 취급하지 마라.
- 주어진 정보의 범위와 작성 결과를 비교할 때 [작성 예시](references/examples.md)를 참고하라.

짧은 문장 한두 개를 작성하는 요청에는 이 문서의 원칙만으로 충분하다. 보고서, 안내문, 절차문처럼 구조 선택이 필요한 글에는 작성 규칙을 먼저 읽어라.

## 출력 전에 내용으로 확인하라

글을 읽으며 다음을 확인하라. 문제가 있는 부분만 고쳐라.

- 제공되거나 확인된 사실의 범위를 벗어나지 않았는가?
- 조건·예외·부정·수치와 확신 수준을 그대로 표현했는가?
- 독자가 주체·대상과 문장 사이 관계를 쉽게 파악할 수 있는가?
- 필요한 설명을 남기고 불필요한 반복을 줄였는가?
- 목적·독자·말투에 맞는 자연스러운 글인가?

이 문서와 참고 문서만으로 판단하라. 규칙 통과 여부나 문장 길이로 글의 품질을 단정하지 마라.
