# wall: 벽은 피하는 것이 아니라 푸는 것이다

## 원칙

막혔다는 것은 틀렸다는 뜻이 아니다. 알려진 방법과 남의 사례로 올 수 있는 데까지 왔고, 이제 **이 문제가 왜 문제인지를 설명하는 지점**에 도착했다는 뜻이다. 거기까지는 준비였고 여기서부터가 과제다. 벽에서 돌아서면 문제를 푼 것이 아니라 문제를 바꾼 것이다.

벽에서 떠오르는 생각이 있다. "이 방향이 아닌 것 같다." "다른 데이터가 필요하다." "남들도 못 했다." 이 생각들은 판단처럼 느껴지지만 벽의 증상이다. 남들이 못 했다는 것은 불가능의 증거가 아니라 "왜 못 했는가"에 대한 가설 하나다. 데이터가 더 필요하다는 말은 지금 있는 데이터를 짜내 보기 전에는 할 수 없다.

## 막혔을 때 하는 것

생각이 떠오르는 그 순간에 한다. 우회안을 떠올리기 전에 한다.

1. **벽을 한 문장으로 쓴다.** 무엇이 무엇을 막는가. 증상이 아니라 막는 메커니즘을 쓴다.
2. **기대고 있는 가정을 나열한다.** 지금까지의 시도가 공통으로 깔고 있는 전제. 입력의 형식, 도구의 동작, 순서, 문제의 범위, 남의 사례가 맞다는 믿음까지.
3. **아직 건드리지 않은 가정 하나를 바꿔 다시 시도한다.** 같은 가정 위에서 반복하는 것은 시도가 아니다. 바꿀 가정이 떠오르지 않으면 2번 목록이 짧은 것이다. 더 캔다.
4. **결과를 기록하고 1번으로 돌아간다.** 벽의 문장이 바뀌었으면 전진한 것이다.

기록 형식은 아래 "벽 블록"이다. docs-convention이 깔린 저장소라면 자기 작업 파일(`docs/log/<작업>.md`)의 작업 기록 절에 쓰고, 아니면 응답 본문에 쓴다. 블록을 쓰는 행위 자체가 이 원칙을 다시 읽는 행위다. 컨텍스트가 길어져도 블록이 원칙을 붙든다.

## "안 된다"의 값

"불가능하다", "우회하자", "다른 데이터가 필요하다"는 **서로 다른 가정을 바꾼 시도가 3개 이상 기록된 뒤에만** 말할 수 있다. 셋은 출발점이고, 사용자가 더 요구하면 더 한다.

그때도 결과는 우회가 아니라 **보고**다. 보고는 시도의 표, 관측한 것, 그리고 "능력이 아니라 X가 없어서 못 푼다"의 X로 끝난다. X는 사람이 줄 수 있는 것이어야 한다. 정보, 권한, 자원, 문제 정의에 대한 결정. 보고를 쓰고 멈춘다. 우회할지, 더 팔지는 사람이 정한다. 사람에게 넘긴다고 우회가 열리는 것이 아니다. 사람의 기본 답은 "더 비틀어라"일 수 있다.

## 벽 블록

시도마다 하나씩 쌓는다.

```
### 벽 n
- 벽: <무엇이 무엇을 막는가, 한 문장>
- 기대고 있는 가정: (1) ... (2) ... (3) ...
- 이번에 바꾸는 가정: (k) → <어떻게>
- 결과: <관측한 것. 벽의 문장이 바뀌었는가>
```

3개 이상 쌓인 뒤 멈출 때:

```
### 벽 보고
| 바꾼 가정 | 관측 |
|---|---|
| ... | ... |
- 없어서 못 푸는 것: <정보 / 권한 / 자원 / 결정 중 하나, 구체적으로>
- 사람에게 묻는 것: <하나>
```

예. CSV 파서가 특정 파일에서만 줄 수를 틀리게 센다. 벽: "따옴표 안의 줄바꿈이 레코드 경계로 읽힌다고 추정되는데 확인이 안 된다." 가정: (1) 파일은 RFC 4180을 따른다 (2) 인코딩은 UTF-8이다 (3) 라이브러리의 기본 옵션이 따옴표를 처리한다 (4) 줄 수 차이는 파서 때문이다. 시도 1은 (3)을 바꿔 옵션을 명시했고 차이가 그대로였다. 시도 2는 (4)를 바꿔 원본을 바이트로 세어 보니 파일에 `\r` 단독 줄바꿈이 섞여 있었다. 벽의 문장이 바뀌었다. 세 번째 시도 전에 풀렸다. "다른 샘플 파일이 필요하다"는 말은 끝까지 나오지 않았다.

## 호출 방식

- `/gudals:wall` 인자 없음: 이 세션에 원칙을 적용한다. 이 문서가 컨텍스트에 있는 것이 적용이다. 사용자에게 "적용했다"고 한 줄만 말하고 하던 일로 돌아간다.
- `/gudals:wall <문제>`: 원칙을 적용하고 그 문제를 바로 시작한다. 시작할 때 첫 벽 블록의 "기대고 있는 가정"을 미리 써 두면 막혔을 때 빠르다.
- `/gudals:wall install`: 현재 디렉터리의 `CLAUDE.md`에 압축 블록(`assets/block.md`)을 넣는다. 이미 있으면 갱신한다. 플러그인 루트의 공용 스크립트를 쓴다. 이 스킬 폴더(호출 시 표시되는 Base directory)에서 두 단계 위가 플러그인 루트다.

  ```bash
  node <플러그인 루트>/scripts/claude-md-block.mjs upsert wall <스킬 폴더>/assets/block.md
  ```

  docs-convention이 깔린 저장소에서는 CLAUDE.md 예산(4,000자)을 넘지 않는지 `node scripts/check-docs.mjs`로 확인한다. 블록은 약 450자다.
- `/gudals:wall remove`: 블록을 뺀다. `remove wall`로 같은 스크립트를 부른다.

install은 선택이다. 리서치 정리나 문서 작업이 주인 디렉터리에는 넣지 않는다. 벽에 부딪히는 과제가 반복되는 디렉터리에만 넣는다.
